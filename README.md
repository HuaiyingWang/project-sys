# Project Desk 接案專案管理

單一 HTML 檔案的接案專案管理工具，無需建置流程。資料存在 Firebase（雲端資料庫），只要打開網址就能看到所有裝置同步的最新紀錄，其他人編輯時畫面也會即時更新。

## 雲端同步設定（第一次使用前必做）

這個工具**只用 Firestore，不用 Firebase Storage**，刻意避開「開通 Storage 必須升級 Blaze 付費方案、要先綁信用卡」的問題，全程不用信用卡。代價是圖片／檔案有大小上限，見下方〈功能〉一節說明。

1. 到 [Firebase Console](https://console.firebase.google.com) 建立一個新專案（免費 Spark 方案即可，不用綁卡）。
2. 左側選單 **Build → Firestore Database**，點「建立資料庫」，模式選哪個都可以（規則等一下會覆蓋），地區選離你近的（例如 asia-east1）。
3. **Firestore Database → 規則**，貼上 [`firebase/firestore.rules`](firebase/firestore.rules) 整份內容取代預設值，然後發布。
4. 左側選單 **專案總覽 → 齒輪 → 專案設定**，往下捲到「你的應用程式」，點 `</>`（網頁）圖示註冊一個新應用程式，會拿到一組設定值。
5. 打開 `index.html`，找到 `FIREBASE_CONFIG`，把裡面的值換成你剛剛拿到的設定：
   ```js
   const FIREBASE_CONFIG = {
     apiKey: "...",
     authDomain: "...",
     projectId: "...",
   };
   ```
6. 存檔、部署（或直接用瀏覽器打開）即可。換版之前，記得先用舊版的「匯出備份」存一份 JSON，等 Firebase 設定好之後再用「匯入備份」灌回來。

**安全性提醒**：這個工具不做登入驗證，只要知道網址就能看到並編輯資料；上面第 3 步的規則是對所有人開放讀寫，等於任何拿得到這組設定值的人都能直接呼叫 API 讀寫（Firebase 的 apiKey 本來就不是機密，安全性是靠規則把關，不是靠藏 key）。這對接案管理這種小規模、非機密等級的用途通常足夠，但**不要**把真正的密碼、金鑰放進備註欄位——FTP 密碼欄位設計上本來就只記「密碼放在哪裡」，不是拿來存密碼本體。如果之後需要更嚴謹的存取控制，可以再加上 Firebase Authentication 登入機制，並把規則改成只允許登入使用者讀寫。

## 功能

- **專案列表**：搜尋、依狀態篩選、多種排序方式（最近更新／建立日期／維護到期日／名稱／業務／待辦需求數）
- **專案基本資料**：狀態、業務、聯絡窗口、上線／到期日等
- **技術資訊**：正式網域、測試站、後台網址、主機、FTP 資訊
- **需求紀錄時間軸**：記錄每筆需求內容、來源窗口、完成狀態
  - 支援貼上、拖放或選擇上傳**圖片**
  - 支援上傳**任何格式的檔案**（PDF、Word、zip 等），**單一檔案上限 700KB**（資料庫直接存文字編碼，不用額外的雲端儲存空間，換來完全免費、免信用卡）
  - 圖片、PDF、純文字檔（.txt/.md/.json/.csv/.log/.yml/.yaml/.xml）可直接在彈窗預覽；其他格式提供下載
- **聯絡窗口管理**：可複用於多個專案
- **備份與還原**：JSON 完整備份（含圖片與檔案），或 Markdown 匯出入（純文字，不含附件內容）
- **GitHub Pages**：已設定部署

## 技術棧

- Vanilla JS（無框架）、單一 `index.html`
- Firebase Firestore 儲存專案、需求、聯絡窗口；圖片與檔案轉成 base64 文字直接存進 Firestore 文件（不用 Firebase Storage，免信用卡），並用 Firestore 的即時監聽推送變更

## 近期更新

- 資料層從瀏覽器本機 IndexedDB 改為雲端資料庫，打開網址即可看到跨裝置同步的最新紀錄，並支援即時更新
